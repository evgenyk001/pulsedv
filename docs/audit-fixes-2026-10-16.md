# Исправления по аудиту 15.10.2026

Исходный снимок: `8166fe8`. Изменения не возвращают отменённое сворачивание главной и не меняют нижний бар.

- F01: согласие открывается внутри окна заявки; контакт и объект не теряются.
- F02–F04: пустая/недопустимая ставка восстанавливает прежнее значение; ручные суммы Select не округляются до шага; нулевой взнос допустим; обычная запись «30 000 рублей в месяц» распознаётся.
- F05–F06: заблокированный сценарий явно описан в CRM без платежа 0; передаются версия, параметры и проекция; черновик отдельный для ЖК/планировки. Медицинские сведения не передаются в CRM/аналитику этим изменением.
- F07: фильтры выплат и очередей применяются перед пагинацией; счётчики Control глобальные; статус приглашения независим от текущей страницы рекомендаций.
- F08: приглашение сохраняется на 7 суток, согласие покупателя по умолчанию выключено. Полный процесс согласования документов и календарь выплаты остаётся задачей отдельной доработки.
- F09–F10: импорт локального избранного связан с серверной сессией; возврат из ЖК поддерживает «Мой поиск».
- F11–F13: дочерние ID каталога имеют составной ключ `(property_id,id)`; используемые фото не удаляются при замене обложки; разделены и объяснены внутренняя/публичная проверки актуальности.
- F14–F16: свежая карточка обновляет нетронутый черновик; фоновый опрос больше не сбрасывает страницы лидов; отметка прочтения требует фактической видимости сообщения и активного окна.
- F17–F19: тайм-аут загрузки 120 секунд вместо 12; просроченные/использованные коды 2FA не доставляются, актуальные приоритетны; проблемные уведомления идут перед свежими успешными. Отдельная пагинируемая очередь всех уведомлений остаётся задачей доработки.
- F20–F21: сетевой сбой отделён от отсутствующего объекта/пустого избранного; есть повтор, состояние пустой карты и причины несовпадения обязательных условий Select.
- F22–F24: штатные баннеры WebP суммарно 398 738 байт вместо 4 379 026; предварительно декодируется первый слайд; новые фото каталога ограничены 2400 px и имеют 800/160 px варианты; второстепенные страницы разделены на chunks; основные разделы и ипотека остаются в стартовом коде для прежнего поведения при обрыве сети. Для старых/внешних фото предусмотрен оригинал при отсутствии производной; массовая переработка старых медиа отдельно не выполнялась.
- F25: показ баннера требует минимум 50% видимости в течение 800 мс. Независимые охваты переименованы и больше не выдаются за последовательную воронку. Полная упорядоченная многосценарная воронка ещё не добавлена.
- F26: технические сессии больше не называются визитами. Серверная классификация тестового трафика и отдельные визиты/когорты ещё не добавлены. Автотесты выполняются в изолированных БД и не создают боевых лидов.

## Новая партнёрская проверка

Подробности: [partner-program.md](partner-program.md). Проверка + предварительная бронь атомарны; свободный номер забронирован на 7 суток, повтор не продлевает срок. После заявки и согласий покупателя из подписанной сессии Telegram система повторяет проверку CRM и создаёт шестимесячный claim. Обычный браузер требует подтверждения контакта владельцем. Архив v2 неизменен; редакция v3 принимается отдельно и требует отдельного разрешения публикации по точной версии.

Важный предел: подтверждённый Telegram удостоверяет аккаунт, но не владение произвольно введённым телефоном. Проверка владения номером через SMS/бот-контакт — следующий отдельный слой. Смена номера и Telegram одного человека требует ручного разбора.

## Проверки

`npm run check`, `npm test`, `npm run build`. Дополнительные регрессионные сценарии: конкурентная бронь одного номера, нормализация телефонов, прямой старый клиент, повтор/idempotency, чужая подтверждённая личность, гостевое обращение/ручная проверка, истечение/снятие брони, фильтрация старого начисления за первой страницей, совпадающие ID планировок в разных ЖК, сохранность общего фото и его производных, истечение 2FA, разделение CRM-контекста и аналитики, сохранение текста v2. Browser-сценарии добавлены в `tests/ui/audit-regressions.spec.ts`.

PGlite подтверждает логику, а PostgreSQL CI проверяет реальные блокировки. Проверка FPS на физических телефонах, реальная нагрузка VPS, восстановление резервной копии и пилот на живых покупателях этим патчем не заменяются.
