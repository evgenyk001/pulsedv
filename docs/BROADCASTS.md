# Анонсы в Telegram

В PULSE Control откройте **Рассылки**. Выберите шаблон или создайте свой анонс, заполните заголовок, текст, фото и кнопку. Для карточки ЖК подойдёт путь `/property/ID` или полная ссылка на карточку. Разрешены также HTTPS-ссылки на правила розыгрыша и другие страницы.

1. Сохраните черновик. Изменённый текст нужно сохранить снова перед отправкой.
2. Нажмите **Отправить себе** и проверьте сообщение в Telegram. Для этого в аккаунте Control должен быть указан ваш Telegram ID и запущен бот.
3. Нажмите **Проверить и отправить**, проверьте предпросмотр и подтвердите отправку всем подписчикам.
4. В этой же карточке нажимайте **Обновить результаты**. Отправляемую рассылку можно остановить. Уже принятые Telegram сообщения не отзываются.

Пользователи включают подписку в мини-приложении: **Профиль → Новости и предложения → Анонсы PULSE.DV**. Изначально подписка выключена. При включении приложение запрашивает у Telegram право бота писать пользователю, если оно ещё не предоставлено; отказ не включает подписку. В каждом анонсе есть кнопка перехода к её настройке. Отключение анонсов не отключает личные сообщения менеджера и напоминания о показах. Новые подписчики не получают ранее запущенные рассылки.

«Отправлено» означает успешный ответ Telegram API, а не прочтение. «Не доставлено» — окончательная ошибка; временные ошибки остаются в очереди до повторных попыток. «Пропущено» — отписка либо отмена. Итоговые счётчики сохраняются отдельно от очищаемой очереди.

В тестовой версии GitHub Pages доступны локальные черновики, фото до 2 МБ и проверка процесса. Сообщения не отправляются и успешная доставка не имитируется. На сервере фото принимаются до 8 МБ, очищаются от метаданных, уменьшаются и преобразуются в JPEG. Текст с фото — до 1024 символов вместе с заголовком.

Для запуска на сервере примените миграцию `024_broadcasts.sql`, настройте `BOT_TOKEN`, публичный HTTPS `PUBLIC_ORIGIN`, постоянное хранилище `MEDIA_ROOT` и worker. Публичные URL `/media/broadcasts/...` должны быть доступны Telegram. Без токена API не запускает отправку. Доступ к рассылкам есть у владельца и администратора, действия записываются в аудит.

Очередь имеет приоритет ниже личных рабочих уведомлений. Повторное нажатие отправки не создаёт вторую запись получателю; при сетевом тайм-ауте после принятия Telegram сообщения повторная доставка технически возможна. Telegram 429 откладывает обработку, постоянные 400/403 завершают конкретную доставку ошибкой. Несколько экземпляров worker используют аренды очереди; при массовом масштабировании дополнительно нужен общий межпроцессный лимитер Telegram.
