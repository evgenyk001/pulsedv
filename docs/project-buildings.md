# ЖК, корпуса и очереди

Обновление включает разделение каталога Control по городам и полировку интерфейса из предыдущего релиза. Ставить предыдущий релиз отдельно не нужно. Для существующего ЖК без корпусов сохраняется прежний интерфейс и логика.

## Что и где заполнять

| Уровень | Данные |
|---|---|
| ЖК | Город, район, адрес, застройщик, класс, общая обзорная подпись срока, стартовая цена, описание, фото, преимущества, документы. Общие итоговые количества квартир и парковочных мест заполняются отдельно. |
| Дополнительно о ЖК | Генплан, технология строительства, высота потолков от (м), вид парковки. Пустые поля не создают вымышленных характеристик. |
| Корпус | Название, очередь/этап, секции, состояние, адрес, год и квартал сдачи, плановая дата ввода, дата передачи ключей по договору, диапазон этажности, всего квартир и квартир в продаже. При необходимости собственные технология и высота потолков. |
| Планировка | Корпус, секция, комнатность, точная площадь/цена или диапазон, изображение, цены по отделке. Денежные поля редактора указаны в рублях; API/CSV `priceFrom`/`priceTo` остаются в миллионах рублей. |

Корпус — самостоятельный дом, очередь — его текстовая принадлежность к этапу проекта. Поля ввода и ключей разделены: это разные события. У корпуса обязательно только название и стабильный ID, технические данные могут уточняться. Для одного корпуса несколько секций перечисляются в «Секции корпуса»; секция конкретной планировки задаётся в её строке.

Общие количества не суммируются автоматически: набор заведённых корпусов может быть неполным. Если один вариант встречается в нескольких корпусах, заведите отдельные строки планировок с разными ID и собственной ценой/привязкой. Непривязанные планировки остаются в общем списке ЖК, но не подмешиваются в выбранный корпус или конкретный срок сдачи.

В мини‑аппе блок появляется только при наличии корпусов/генплана. Есть быстрый выбор корпуса, карточки, раскрытие дополнительных корпусов (первые шесть сразу), отдельные даты и характеристики. Цена и ипотека выбранного корпуса рассчитываются по его подтверждённым планировкам. Если их нет или цена неизвестна, показывается уточнение. Генплан открывается в панели с увеличением до 300% и прокруткой. Корпус и секция выбранной планировки передаются в контекст заявки Control.

Технология и потолки на уровне ЖК — общие данные; значения корпуса позволяют указать отличия. Инфраструктура и преимущества по-прежнему заполняются в «Особенностях», презентации и проектные материалы — в «Документах».

## Массовый импорт

Кнопка «Скачать шаблоны» выдаёт шесть файлов. `pulse-buildings.csv` связывается с `pulse-objects.csv` через `propertyId`; `buildingId` в `pulse-floorplans.csv` ссылается на `id` корпуса в пределах того же ЖК. Корпус и планировка должны иметь стабильные разные ID; название можно менять.

Поля корпусов: `propertyId,id,name,phase,sections,status,address,deliveryYear,deliveryQuarter,commissioningDate,handoverDate,floorsFrom,floorsTo,totalApartments,availableApartments,constructionType,ceilingHeight`. Статусы: `unknown`, `planned`, `building`, `completed`. Даты: `YYYY-MM-DD`, квартал: 1–4. Пустое значение — неизвестно; 0 квартир в продаже — подтверждённое нулевое наличие.

Основной CSV также поддерживает `masterplanUrl,constructionType,ceilingHeight,parkingType`; парковка: `underground`, `multilevel`, `surface`, `mixed`. Для генплана загрузите изображение в галерею и используйте его `/media/` URL либо HTTPS-ссылку.

Файл корпусов применяется к перечисленным ЖК целиком. Импорт подтверждает заменяемые разделы до записи; API выполняет весь пакет транзакционно. Без файла корпусов существующие корпуса сохраняются. Старые CSV планировок без колонок `buildingId`/`sectionLabel` сохраняют прежние привязки совпадающих ID; явная пустая колонка очищает привязку. Пропущенные общие даты/количества не обнуляются при добавлении структуры. Удаление корпуса в редакторе оставляет его планировки без привязки.

## Совместимость и поиск

Структура хранится в `catalog_properties.project_details`. Аддитивная миграция `034_project_buildings.sql` добавляет nullable `building_id` и `section_label` и индекс в таблицу планировок. Существующие строки остаются без привязки. Старый клиент, не приславший новые поля, сохраняет связи по ID планировки; явный `null` снимает связь.

Метаданные годов и фильтр «Сдан» используют корпуса, если они заданы. SQL-поиск и PULSE Select связывают срок, комнатность и бюджет с одной планировкой одного корпуса. Дешёвый вариант поздней очереди не доказывает соответствие раннему сроку. Простой ЖК без структуры использует прежний общий срок. Публичная карточка каталога остаётся обзором всего ЖК; точные варианты открываются через выбор корпуса.

## Проверка и установка

Проверяются схемы, ссылки, диапазоны, даты, общий/корпусный бюджет, SQL-фильтры, метаданные, старые клиенты и импорт с сохранением данных. Браузерные сценарии включают создание/редактирование/удаление корпусов, выбор планировки, возврат из ипотеки, неизвестную цену, генплан, мобильные размеры и реальный Fastify + изолированную PGlite базу для импорта CSV и сохранения.

Используйте закреплённый по коммиту `deploy/update-project-buildings.sh`. Он принимает только ожидаемую миграцию, проверяет локальные настройки, сохраняет конфигурацию/старые образы, делает дамп БД и архив медиа, проверяет их читаемость, затем применяет миграцию и проверяет образы, новые столбцы, `/ready`, HTML Control и Mini App и www-перенаправление. При ошибке возвращаются прежние образы; аддитивные столбцы могут остаться. Автоматического восстановления БД поверх новых пользовательских изменений нет. Установка на VPS и реальный iPhone проверяются после запуска блока PuTTY; локальные проверки выполнялись в Chromium.
