# Interest DNA v1

Общий детерминированный движок: `packages/interest-dna/index.ts`. Никакого внешнего AI, fingerprinting или поиска персональных данных. Визуализации используют CSS; дополнительные библиотеки и ключи не нужны.

## Данные и смысл

- Окно — 30 дней. Период полураспада веса — 14 дней.
- Вес сигнала: просмотр ЖК 2, просмотр планировки 5, избранное 9, сравнение 4, форма консультации 7, успешная отправка ссылки 3, фильтры 4, завершённый подбор 12. Ипотечные сценарии: выбор 3, расчёт 5.
- Не более трёх одинаковых сигналов по значению и типу за день, даже между связанными сессиями. Повтор одного event ID игнорируется.
- Шкала 0–100 — сумма затухающих весов / 30 × 100 с ограничением сверху. Это не вероятность сделки и не доля интереса.
- Уверенность: ранний сигнал; 3 учтённых действия — подтверждающие действия; 5 действий в 3 разных днях — устойчивый интерес.
- Факты берутся только из последнего завершённого PULSE Select. Бюджет не выводится из цены просмотренного ЖК или калькулятора. Выбор программы не подтверждает право на льготу. Сдача дома не считается сроком покупки.
- Изменения — различия последних двух завершённых подборов, возвращение после паузы от 3 дней, актуальное добавление в избранное. Это не список «непрочитанного после звонка».
- Просмотр планировки фиксируется после 1 секунды видимости не менее 60% карточки в активной вкладке.
- Рекомендации — до трёх опубликованных ЖК по явным параметрам последнего подбора. При неполных финансовых данных рекомендации не строятся.

## Сервер и права

`GET /api/v1/control/interest/:sessionId` требует вход сотрудника. Связывает сессии исключительно через `user_id`, присвоенный после проверки подписи Telegram. Совпадение телефона не объединяет историю.

Владелец/администратор получают связанную историю. Менеджер получает только сессии назначенных ему клиентов; запрос чужого профиля возвращает 404. Профиль считает последние 5000 событий, API явно сообщает об ограничении. Каталог рекомендаций ограничен 2000 объектами, превышение также помечено.

В демонстрации используется тот же движок поверх событий браузера. Внешних отправок нет. Обновление профиля: при открытии, обновлении CRM и по кнопке; исторические веса пересчитываются на текущий момент, отдельная фоновая очередь для этого не требуется.

## Уведомления

Существующая транзакционная очередь используется для `manager.interest_changed`. Только активные заявки с менеджером, изменения завершённого запроса или возвращение после перерыва, события не старше пяти минут. Не чаще одного уведомления о DNA на заявку за 12 часов; уникальный индекс защищает от повторной отправки одного изменения. Сейчас уведомления привязаны к сессии заявки; DNA-карточка может объединять несколько проверенных сессий.

Отправка выполняется существующим worker после настройки Telegram на VPS. Новых пользовательских рассылок нет.

## Развёртывание

Обычный запуск миграций применяет `005_interest_dna.sql`: индекс истории по пользователю и индексы дедупликации/паузы уведомлений. Затем развернуть API, worker и frontend вместе. На GitHub Pages доступна демонстрация DNA; межустройственная история и Telegram-уведомления требуют серверного режима.
