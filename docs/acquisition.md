# Посещения и источники PULSE.DV

В PULSE Control → Аналитика → «Откуда приходят клиенты» показаны визиты на лендинг, визиты с кликом в Telegram, подтверждённые открытия после лендинга, все визиты в приложение и визиты с заявкой. Период — 90 дней. Метрики не означают число физических людей. Один визит — одна вкладка браузера, пока между регистрациями визита не прошло 30 минут; новый utm_source начинает новый визит. Обновления страницы не создают дублей. У разных вкладок и устройств разные визиты.

В том же блоке создаются ссылки с utm_source, utm_medium, utm_campaign, utm_content. Для разных площадок, кампаний и объявлений используйте разные ссылки. Поддерживается также utm_term. Сначала используются UTM, при их отсутствии — домен document.referrer. Полный URL источника, его параметры, IP и контактные данные в таблицу посещений не записываются. При скрытом источнике используется «Прямой / источник неизвестен».

Лендинг регистрирует визит в своём API. После успешной регистрации кнопки Telegram получают непрозрачную метку acq_, а QR-код заменяется персональным QR той же ссылки. Метка содержит только случайный идентификатор посещения и не даёт доступа к аккаунту. Сканирование QR с компьютера на телефоне связывается с лендингом через startapp, даже без общих cookies. Загрузка картинки QR не считается кликом. Связь подтверждается сервером только после проверки подписи Telegram initData. Метка действует 30 дней. Для обычного браузерного перехода на том же домене есть HttpOnly-cookie. Метки аналитики не участвуют в закреплении партнёрских клиентов и выплатах.

Первый источник технической сессии сохраняется для существующей CRM-аналитики. Последующие визиты учитываются отдельно. «Визиты с заявкой» считаются по первому посещению сессии и не дублируются при обновлениях; повторный вход не перезаписывает первоначальный источник. Несколько заявок одной сессии считаются одним посещением с заявкой. Это модель первого касания сессии, а не установление личности человека между браузерами.

Общая статистика доступна владельцу и администратору. Менеджеры сохраняют доступ к прежней статистике назначенных клиентов. API проверяет права и ограничивает частоту запросов. Повторы регистрации и событий с тем же UUID не увеличивают счётчики. Максимум 500 сочетаний меток в ответе помечается явным предупреждением.

Переход по кнопке учитывается серверным перенаправлением на Telegram, не задерживающимся на отправку клиентской аналитики. Счётчик показов QR не используется. Журнал посещений удаляется обслуживанием по ANALYTICS_RETENTION_DAYS (по умолчанию 180 дней), отчёт показывает последние 90 дней.

Для запуска: применить миграцию 022, развернуть API и обе веб-части на pulsedv.ru, включить Main Mini App для @pulsedvbot в BotFather и указать адрес мини-аппа; настроить BOT_TOKEN и TELEGRAM_BOT_USERNAME. На статическом GitHub Pages общего сбора нет; прежние ссылки продолжают открывать бота. После развёртывания проверить реальный переход с телефона и сканирование QR с другого устройства: тестовые визиты → кнопка/QR → открытие → заявка должны появиться в Control под метками тестовой кампании.

Абсолютно полного учёта нет: блокировщики, отключённый JavaScript, недоступность API, боты и пересылка чужой ссылки влияют на данные. Клиентские UTM и referrer являются рекламными сигналами, а не удостоверением происхождения. Данные до подключения счётчика не восстанавливаются. Измерение клика не означает, что Telegram открылся. Текущий сбор не фильтрует всех ботов и не является биллинговым источником для оплаты рекламы.
