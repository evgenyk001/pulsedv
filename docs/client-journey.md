# Сопровождение клиента — v1

## Где находятся функции

- Control → Лиды → карточка → «Подборки и показы»: черновик подборки из 1–10 опубликованных ЖК, комментарии менеджера, публикация/снятие, ответы клиента, показы и следующий шаг со сроком.
- Mini App → Профиль → «Мои подборки и показы»: только собственные обращения, опубликованные варианты, реакция и свободный комментарий; запрос времени показа. Время вводится и показывается по Владивостоку (UTC+10).
- Control → «Подборки и показы»: календарь по дню, очередь клиентов без следующего шага, просроченные договорённости и проверка актуальности каталога. Следующие шаги также видны в разделе «Задачи», отдельно от автоматически создаваемых задач первичного контакта.
- Mini App → Избранное: сравнение 2–3 ЖК, таблица с режимом «Только различия», расположение, цена, сдача, класс, комнатность, отделка и платёж по общему сценарию. Параметры ставки, взноса и срока редактируются. Выбранный список сохраняется в браузере; просмотры сравнения передаются в историю клиента.
- Control → Аналитика: первый источник сессии и кампания, визиты, контакты, состоявшиеся показы и сделки. UTM передаются в URL Mini App; проверенный Telegram start_param используется при отсутствии UTM. Воронка считает уникальные сессии, а не людей; окно сессий 90 дней. Показы считаются по явно завершённым встречам. Для старых сделок используется текущий статус, для новых сохраняются переходы этапов. Менеджер видит только назначенные сессии — это не общая конверсия рекламы.

## Данные и ограничения доступа

Миграция `006_client_journey.sql`: `client_journeys`, `catalog_verifications`, `lead_stage_events`.
Одна версия документа на лид. Все изменения проходят через команды, блокировку лида и сравнение revision; устаревшая запись получает 409. Сервер не принимает готовый документ от клиента.
Клиент имеет доступ по серверной сессии либо подтверждённому Telegram user_id. Телефон не объединяет карточки. Менеджер имеет доступ только к назначенным лидам. Клиент не видит черновики, следующий шаг сотрудника и внутренний результат показа; не может менять публикацию или подтверждать встречу. Реакцию оставляет только клиент.
Подтверждение требует назначенного менеджера. Блокировка сотрудника и проверка соседних подтверждённых встреч исключают подтверждение двух показов ближе часа. Это фиксированная продолжительность слота, не оценка времени дороги. Для переноса отмените показ и создайте новый запрос. Закрытые обращения доступны для чтения.

Реакции и запросы показа записываются в журнал; последняя реакция отражается в Interest DNA. «Дорого» не меняет бюджет автоматически. Сводка строится по фактам, без внешнего AI.

## Актуальность

Администратор подтверждает цену и наличие после сверки с застройщиком и может добавить публичное пояснение. Через 7 дней нужна повторная проверка. В API изменение каталога после проверки также делает её устаревшей. Карточка ЖК показывает дату и оговорку о наличии конкретной квартиры. Это ручная проверка, не онлайн-интеграция с застройщиком.

## GitHub Pages и VPS

На Pages работают сценарии в localStorage: для демонстрации клиента и менеджера используйте одну вкладку, переходя между Mini App и Control. Клиентские обращения привязаны к текущей сессии вкладки. Никаких реальных уведомлений из демонстрации не отправляется.
На VPS после миграций и настройки Telegram применяется серверная авторизация; очередь уведомлений сообщает о публикации подборки, изменении показа и ответе клиента. Доставка требует привязанного Telegram и запущенного worker. Автоматические напоминания за час, синхронизация с внешним календарём, рекламные расходы/ROI и API застройщиков в v1 не включены.

Лимиты v1: 1000 последних обращений в сопровождении, до 50 подборок и 100 показов на обращение, первые 2000 проверок объектов, 500 сочетаний рекламного источника и кампании. Интерфейс предупреждает о лимите обращений и источников. Для текущего каталога до 1000 ЖК достаточно; рост дальше требует пагинации сопровождения.

## Проверки перед запуском

Автоматические проверки покрывают собственную/чужую сессию, права менеджера, скрытие черновиков, подмену реакции сотрудником, конфликт версии, закрытый лид, переходы показа и результат, актуальность каталога, аналитику и полный демонстрационный путь на 390 и 1440 px.
На VPS дополнительно проверить два реальных Telegram-аккаунта, выдачу персональных подборок между устройствами, доставку сообщений, часовой пояс, резервную копию и восстановление БД. Все проверки выполнять на тестовых клиентах до подключения рекламы.
