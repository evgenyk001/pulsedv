# Новогодняя акция

Раздел Control → Розыгрыш доступен владельцу и администратору. По умолчанию акция выключена, правила пустые. До публикации организатор заполняет полные правила, уточняет модель, комплектацию, цвет и срок вручения приза, условия допуска и дату определения победителя. Изображение смартфона — художественная визуализация.

Даты по умолчанию: 6 ноября 2026, 00:00 → 2 января 2027, 00:00 (конец не включается), время Владивостока. Таким образом, 1 января включено целиком. Определение победителя по умолчанию 15 января, 12:00 — время можно изменить **до первой заявки**. Это расписание, автоматического выбора победителя в этом изменении нет.

Клиент с подтверждённым телефоном принимает правила и подаёт заявку. Повторный запрос возвращает ту же запись. Заявка не даёт номера. Клиенту предлагается связаться с менеджером через существующий диалог покупки. После государственной регистрации сделки владелец/администратор выбирает связанное с этим аккаунтом обращение со статусом «Сделка», указывает фактическое время регистрации и реквизиты подтверждения. Проверка документов остаётся ручной: интеграции с государственным реестром нет.

Сервер проверяет принадлежность сделки, статус, период регистрации и предшествующую заявку. Подтверждение и создание уникального номера/уведомления — одна транзакция. Один аккаунт, телефон и сделка не получают повторные номера. Номер виден в Mini App; уведомление отправляет существующий worker. При ошибке Telegram оно повторяется по общей политике очереди, ошибка видна в Control. Удаление/повторное использование номера не предусмотрено; отзыв допуска сохраняет историю.

После первой заявки приз, даты и правила фиксируются. Публикацию можно выключить, заголовок изменить. Полные правила хранятся в настройках, принятая версия записана в заявке. Для иной акции потребуется отдельная кампания, а не переписывание принятых условий.

Баннер встроен в существующую карусель. Восемь частиц снега и мягкий блик анимируются CSS transform/opacity только на текущем видимом слайде и активной вкладке. При prefers-reduced-motion они отключены. Счётчик опирается на время сервера и монотонный таймер браузера; API всё равно проверяет сроки независимо от интерфейса.

Обновление: `deploy/update-giveaway.sh <проверенный SHA>`. Требуются текущие api/worker/web, Docker Compose, Python 3 и свободное место под резервную копию. Старые образы сохраняются локальными тегами; если метаданные образа недоступны, создаётся локальный снимок существующего контейнера перед остановкой. Эти снимки содержат конфигурацию контейнера, включая окружение, и не должны публиковаться в registry. Установщик проверяет восстановление дампа в отдельной БД, целостность медиа, применяет добавочную миграцию 035, пересоздаёт сервисы и сверяет файлы API/worker, HTTPS и HTML. При ошибке возвращает прежние образы, не восстанавливая БД поверх новых записей. Материалы и команды Compose для восстановления находятся в `/root/pulsedv-giveaway-recovery.*`.

Проверено локально: типизация всех рабочих пространств, сборка обоих интерфейсов, серверные регрессионные тесты (включая права, подтверждение номера, заморозку правил, принадлежность сделки, идемпотентность, уведомления и часовой пояс). Реальную доставку Telegram и производственный Docker проверяют после установки на VPS.

## Отправка ЖК

Кнопка «Поделиться» в карточке ЖК теперь использует Telegram Mini App deep link, а не URL браузерной страницы. В клиентах с поддержкой `shareMessage` API готовит сообщение с названием, городом и кнопкой «Открыть ЖК в PULSE». Адрес кнопки — `t.me/<bot>?startapp=property_<base64url(id)>`, поэтому подходит и для групп/каналов; `web_app`-кнопки здесь не используются. Получателя выбирает пользователь в штатном диалоге Telegram. Сам API никому сообщение не отправляет. Для старых клиентов или сбоя подготовки отправляется та же Telegram-ссылка через доступный диалог отправки/копирование.

Маршрут из startapp применяется после проверки Telegram-идентичности и сохраняется за экраном обязательного подтверждения номера. Параметр служит только навигации; права доступа он не даёт. Подготавливаются только опубликованные ЖК, идентификатор отправителя берётся из сессии на сервере. Закрытие диалога не считается отправкой и не запускает второй диалог. Ранее отправленные браузерные ссылки этим изменением не преобразуются.
