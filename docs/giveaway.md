# Новогодняя акция

Раздел Control → Розыгрыш доступен владельцу и администратору. По умолчанию акция выключена, правила пустые. До публикации организатор заполняет полные правила, уточняет модель, комплектацию, цвет и срок вручения приза, условия допуска и дату определения победителя. Изображение смартфона — художественная визуализация.

Даты по умолчанию: 6 ноября 2026, 00:00 → 2 января 2027, 00:00 (конец не включается), время Владивостока. Таким образом, 1 января включено целиком. Определение победителя по умолчанию 15 января, 12:00 — время можно изменить **до первой заявки**. Это расписание, автоматического выбора победителя в этом изменении нет.

Клиент с подтверждённым телефоном принимает правила и подаёт заявку. Повторный запрос возвращает ту же запись. Заявка не даёт номера. Клиенту предлагается связаться с менеджером через существующий диалог покупки. После государственной регистрации сделки владелец/администратор выбирает связанное с этим аккаунтом обращение со статусом «Сделка», указывает фактическое время регистрации и реквизиты подтверждения. Проверка документов остаётся ручной: интеграции с государственным реестром нет.

Сервер проверяет принадлежность сделки, статус, период регистрации и предшествующую заявку. Подтверждение и создание уникального номера/уведомления — одна транзакция. Одна заявка связана с одним аккаунтом и подтверждённым телефоном. Одна зарегистрированная сделка получает один номер; несколько разных сделок клиента получают отдельные номера. Повторное подтверждение той же сделки не создаёт номер или уведомление заново. Все номера видны в Mini App; уведомление отправляет существующий worker. При ошибке Telegram оно повторяется по общей политике очереди, ошибка видна в Control. Удаление/повторное использование номера не предусмотрено; отзыв допуска сохраняет историю.

После первой заявки приз, даты и правила фиксируются. Публикацию можно выключить, заголовок изменить. Полные правила хранятся в настройках, принятая версия записана в заявке. Для иной акции потребуется отдельная кампания, а не переписывание принятых условий.

Баннер встроен в существующую карусель. Восемь частиц снега и мягкий блик анимируются CSS transform/opacity только на текущем видимом слайде и активной вкладке. При prefers-reduced-motion они отключены. Счётчик опирается на время сервера и монотонный таймер браузера; API всё равно проверяет сроки независимо от интерфейса.

Обновление: `deploy/update-giveaway.sh <проверенный SHA>`. Требуются текущие api/worker/web, Docker Compose, Python 3 и свободное место под резервную копию. Старые образы сохраняются локальными тегами; если метаданные образа недоступны, создаётся локальный снимок существующего контейнера перед остановкой. Эти снимки содержат конфигурацию контейнера, включая окружение, и не должны публиковаться в registry. Установщик проверяет восстановление дампа в отдельной БД, целостность медиа, применяет добавочные миграции 035 и 036, пересоздаёт сервисы и сверяет файлы API/worker, HTTPS и HTML. При ошибке возвращает прежние образы, не восстанавливая БД поверх новых записей. Материалы и команды Compose для восстановления находятся в `/root/pulsedv-giveaway-recovery.*`.

Проверено локально: типизация всех рабочих пространств, сборка обоих интерфейсов, серверные регрессионные тесты (включая права, подтверждение номера, заморозку правил, принадлежность сделки, идемпотентность, уведомления и часовой пояс). Реальную доставку Telegram и производственный Docker проверяют после установки на VPS.

## Объединённый релиз

Обновление включает розыгрыш, Telegram-ссылки «Поделиться ЖК» и отправку PDF-презентаций в личный бот. Устанавливается одной командой `deploy/update-giveaway.sh <SHA>` поверх прежнего релиза или отдельного релиза sharing/PDF. Переработка визуального оформления Control из отдельной экспериментальной ветки не включена.

После установки акция остаётся выключенной, если ранее не публиковалась. Владелец открывает Control → Розыгрыш, заполняет полные правила, проверяет приз и сроки, включает публикацию и сохраняет. Нажатие клиента создаёт заявку и уведомление без номера; номер и отдельное уведомление появляются после ручной проверки связанной сделки со статусом «Сделка» и её регистрации. Подтверждение документов не автоматизировано. Кнопка «Проверить» позволяет добавить следующую сделку уже допущенного клиента. Отклонение участия отзывает допуск всех номеров заявки и сохраняет их историю. Розыгрыш победителя автоматически не выполняется.

## Страница участия

Обновлённая страница объединяет приз и отсчёт в один бордовый блок. Сразу под ним — заявка либо её актуальный статус; выданные номера отображаются билетами. «Связаться с менеджером» использует штатный вход в переписку: открывает активное обращение или подготовку нового сообщения. Правила закрыты в доступном с клавиатуры раскрывающемся блоке; текст из Control сохраняется целиком, без сокращений. Ссылка «Прочитать правила» раскрывает и фокусирует этот блок. В Telegram используется нативная кнопка назад, в браузере остаётся общая кнопка BackLink. Веб-обновление `deploy/update-giveaway-page.sh <SHA>` не меняет API, worker, БД и содержимое правил. Перед установкой сохраняет прежний web, при отсутствии метаданных образа делает локальный снимок контейнера. Проверяет HTML, основной JS/CSS, ленивый скрипт страницы конкурса и /ready через HTTPS.

Для визуальной проверки на синтетических данных: `vite build --config tests/fixtures/giveaway/vite.config.ts`. Фикстура использует настоящие компоненты страницы и оболочки, не обращается к рабочему API, поддерживает `state=new|pending|confirmed|multiple|rejected|ended|future|paused`, `width=320|390|430|768`, `native=0` и `long=1`. В обычную сборку и Docker-образ фикстура не входит.
