# Допуск PULSE.DV к запуску на VPS

Проверка кода и успешная публикация GitHub Pages не подтверждают настройку конкретного VPS. Pages работает в деморежиме; Docker-образ web собирает Mini App и Control в режиме API.

## Что проверяет репозиторий

- TypeScript, обе сборки, серверные и браузерные сценарии Chromium/WebKit.
- Реальный PostgreSQL 16 в CI, миграции, роли и изоляцию клиентов, повторные заявки, точность сумм, конкурентное закрепление партнёром.
- Сборку API/web-образов и конфигурацию Caddy.
- `deploy/smoke.sh`: отдельный Compose-проект, HTTPS через Caddy, все публичные оболочки и их JS/CSS, Secure/HttpOnly cookie владельца, отказ без авторизации, создание ЖК, загрузку и выдачу фото, заявку и её повтор без дубля, сохранение цены/заявки/фото после перезапуска, `pg_dump` и `pg_restore` в изолированном контейнере.
- `/ready` отклоняет схему с неприменёнными миграциями. API и worker имеют healthcheck; логи контейнеров ограничены ротацией.

Тестовый Compose использует только случайный loopback-порт и отдельные одноразовые тома. Не запускайте `deploy/compose.smoke.yaml` на боевом проекте.

## Что требуется на целевом сервере

1. Настоящий домен, корректные A/AAAA, доступные 80/443, Docker Compose v2. Копия репозитория в `/opt/pulsedv`, `.env` с правами 600.
2. Случайный URL-safe пароль PostgreSQL от 32 символов, реальный токен и имя Telegram-бота, ключ 2GIS с ограничением по домену, реквизиты оператора. Утверждение оферты фиксируется отдельно; код его не выполняет.
3. Перед стартом: `docker compose build`, затем `docker compose run --rm --no-deps api node --import tsx backend/src/preflight.ts`. Ошибки блокируют этот проверочный шаг. Предупреждение о неопубликованной оферте означает, что новые партнёры пока не смогут принять условия. Скрипт не проверяет внешние сервисы и не запускается автоматически при обычном `up`.
4. Применить миграции, создать владельца, запустить контейнеры по `deploy/README.md`. Проверить `/ready`, Docker healthcheck, вход владельца и менеджера с разными правами.
5. Проверить Telegram в настоящем Mini App: URL в BotFather, пользователь и сотрудники нажали «Старт», подпись initData, сообщение менеджеру, код 2FA. Включить 2FA до работы с клиентами и сохранить способ восстановления доступа.
6. Загрузить реальные опубликованные ЖК, фото и планировки. Проверить на телефоне каталог → ЖК → ипотека → заявка → Control → ответ клиенту; отдельно карту и закреп партнёром с двух аккаунтов. Проверка телефона не подтверждает владение номером: SMS/контактная верификация пока не реализована.
7. Настроить внешний Restic, пароль вне сервера, backup/monitor timers и внешний heartbeat. Выполнить первую копию, восстановить её на отдельном тестовом хосте, открыть восстановленное приложение и вложения. CI подтверждает технический dump/restore, но не внешнее хранилище и расписание конкретного VPS.

## Границы готовности

Репозиторий содержит запускаемый серверный стек и автоматические проверки. Полный допуск к реальным клиентам возможен после прохождения пунктов целевого сервера. Без доступа к нему нельзя подтвердить DNS, сертификат, реальные ключи, доставку Telegram, резервное хранилище и восстановление именно его данных. Выплаты партнёрам по-прежнему выполняются вручную; приложение учитывает начисления и подтверждение перевода.
